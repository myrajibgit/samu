# Running 100% Offline AI on Your Android Phone

This build runs **real LLMs 100% offline on your phone** — no API key, no cloud, no NDK setup.

The chat is powered by [llama.cpp](https://github.com/ggerganov/llama.cpp) native bindings
(`io.github.ljcamargo:llamacpp-kotlin`, bundled as a Gradle dependency — the native `.so`
files for `arm64-v8a` and `x86_64` ship inside the app). Download a GGUF model once
(1 tap in the **Models** tab), and every token is generated by your phone's CPU.

## Build & Run

1. Open the project in **Android Studio** (Koala or newer) and let Gradle sync.
   - No NDK, no CMake, no `jniLibs`, no `.env` file required.
2. Enable **Developer Options → USB Debugging** on your phone
   (Settings → About phone → tap Build number 7×).
3. Plug the phone in, select it in the device dropdown, press **Run ▶**.
   - Emulators work too (x86_64 is supported) — great for a quick smoke test.

## Secrets via Infisical (optional)

PocketLLM builds and runs with **zero secrets**. When you eventually need them
(e.g. release-signing credentials), they are delivered centrally by
[Infisical](https://infisical.com) instead of a `.env` file on disk:

```bash
# one-time setup
winget install infisical.infisical
infisical login        # opens your browser
infisical init         # links this folder (writes .infisical.json — safe to commit)

# import keys: drag & drop your old .env (or .env.example) onto the
# Secrets Overview page at https://app.infisical.com

# then run builds through the wrapper — secrets arrive as env vars:
infisical run --env=dev -- ./gradlew assembleDebug
infisical run --env=dev -- ./gradlew assembleRelease   # needs KEYSTORE_PATH/STORE_PASSWORD/KEY_ALIAS/KEY_PASSWORD
```

Confirm delivery without ever printing a value — check the length only:

```bash
infisical secrets get GEMINI_API_KEY --plain | tr -d '\n' | wc -c
```

Then rename `.env` to `.env.backup` and rerun the wrapped build — if it still
works, secrets are coming from Infisical, not disk.

## First Chat (airplane-mode friendly)

1. **Models** tab → tap **Download** on a model that fits your RAM:
   | Model | Size (Q4_K_M) | RAM needed |
   |---|---|---|
   | SmolLM2 135M Instruct | ~95 MB | any phone |
   | SmolLM2 360M Instruct | ~242 MB | 2 GB |
   | Qwen 2.5 0.5B Instruct | ~380 MB | 2–3 GB |
   | TinyLlama 1.1B Chat | ~669 MB | 3 GB |
   | Llama 3.2 1B Instruct | ~805 MB | 3–4 GB |
   | DeepSeek R1 Distill 1.5B | ~1.1 GB | 4 GB+ (streams `<think>` reasoning) |
   | Gemma 2 2B Instruct | ~1.65 GB | 5 GB+ |
2. (Optional) Tap **Load in RAM** to pre-load the model so the first reply is instant.
3. **Chat** tab → pick the model → send a message.
   The first message loads the model into RAM (progress shown), then tokens stream
   from your CPU with live tokens/sec stats. Tap **Stop** to cut generation short.
4. Turn on **Airplane Mode** and keep chatting — everything stays on-device.

## How it works (no fakes)

- The GGUF file lands in the app's private storage (`filesDir/models/<id>.gguf`).
- `LlamaCppEngine` wraps the llama.cpp bindings: it opens the file by descriptor,
  builds the native context (`n_ctx` from the model card, batch 512, all CPU threads),
  and streams tokens back as Kotlin coroutines events.
- Prompts are rendered with the model family's chat template
  (`PromptFormatter`: Llama-3, ChatML, DeepSeek, TinyLlama, Gemma).
- There is **no cloud fallback and no canned-response path**: if the model isn't
  downloaded, the chat tells you to download it. If RAM is insufficient, the load
  fails with a suggestion to try a smaller model.

Optional: the **Gemini API key** field in Settings still exists for a cloud-assist
via `GeminiCloudService`, but the chat never uses it — fully optional.

## Advanced: upgrading the native core

The binding's llama.cpp core is pinned upstream. To bump it or build from source,
clone [kotlinllamacpp](https://github.com/ljcamargo/kotlinllamacpp) and publish/replace
the AAR (NDK r27c + CMake 3.22.1 needed for the C++ build) — daily app development
never touches native code.
